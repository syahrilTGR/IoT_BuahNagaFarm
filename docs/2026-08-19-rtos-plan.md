**Tanggal:** 2026-08-19
**Status:** Planning
**Branch:** `feature/rtos-refactor`

## Goal

Refactor firmware ke FreeRTOS (3 task) agar buzzer & sensor tidak pernah blocking satu sama lain.

---

## Task Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                      SMARTNAGA RTOS                         │
├──────────────────────┬──────────────────────┬────────────────┤
│   TASK BUZZER        │   TASK SENSOR        │  TASK NETWORK  │
│   (priority 3)       │   (priority 2)       │  (priority 1)  │
│   stack: 2048        │   stack: 4096        │  stack: 4096   │
├──────────────────────┼──────────────────────┼────────────────┤
│ - buzzer_on/off      │ - readPZEM()         │ - sendToFirebase()
│ - pln_alarm_repeat   │ - readZMPT()         │ - checkFirebaseCmds()
│ - toggle beep        │ - updateOLED()       │ - heartbeat
│ - silence_gap check  │ - queue data to NET  │ - queue data to SENSOR
├──────────────────────┼──────────────────────┼────────────────┤
│ PERIOD: 50ms         │ PERIOD: 100ms/1s/5s  │ PERIOD: 1s     │
│ QUEUE: buzzer_cmd    │ QUEUE: sensor_data   │ QUEUE: net_cmd │
└──────────────────────┴──────────────────────┴────────────────┘
```

## Queue Structure

```cpp
// Buzzer command queue (from Sensor/Network → Buzzer)
struct BuzzerCmd {
    enum Type { BEEP_200, BEEP_500 };
    Type type;
};
QueueHandle_t buzzerQueue;

// Sensor data queue (Sensor → Network)
struct SensorData {
    float blockA_V, blockA_I, blockA_P, blockA_E;
    float blockB_V, blockB_I, blockB_P, blockB_E;
    float zmpRms;
    bool plnAvailable;
    uint32_t timestamp;
};
QueueHandle_t sensorQueue;

// Network command queue (Network → Sensor/Buzzer)
struct NetCmd {
    enum Type { SET_LAMP_A, SET_LAMP_B, REQ_SYNC };
    Type type;
    bool state;
};
QueueHandle_t netCmdQueue;
```

## Priority & Timing

| Task | Priority | Period | Notes |
|------|----------|--------|-------|
| Buzzer | 3 (high) | 50ms | Must never miss deadline |
| Sensor | 2 (med) | 100ms/1s | Blocking allowed |
| Network | 1 (low) | 1s | Can lag, non-critical |

**Priority inversion avoidance:** Gunakan `xQueueSend/Receive` dengan timeout, bukan mutex.

---

## Migration Checklist

| Legacy Code | RTOS Replacement |
|-------------|------------------|
| `loop()` | 3 tasks + queues |
| `Timer` struct + `millis()` | `vTaskDelayUntil()` / task period |
| `buzzerOn()` | `xQueueSend(buzzerQueue, ...)` |
| `readPZEM()` blocking | Sensor task internal |
| `sendToFirebase()` blocking | Network task internal |
| Global vars (`acVoltage`, `blockA`, etc) | Queue/notification passing |

## Rollback Plan

Jika RTOS gagal / crash:
- Branch terpisah `feature/rtos-refactor`
- Commit tiap phase untuk bisect
- Tag `pre-rtos` untuk rollback cepat

---

## Risks & Mitigation

| Risk | Mitigation |
|------|------------|
| Stack overflow | `configCHECK_FOR_STACK_OVERFLOW=2`, `uxTaskGetStackHighWaterMark()` |
| Priority inversion | Queues + timeout, no mutex |
| Watchdog reset | Buzzer task feed watchdog; `CONFIG_ESP_TASK_WDT_TIMEOUT_S=30` |
| Queue full | `xQueueSend` timeout 0 (non-blocking), log drop |

## Success Criteria

- [ ] Buzzer beep 200ms/500ms **tidak pernah miss** walau Firebase timeout 30s
- [ ] PLN off → beep 500ms/3s **bersih tanpa overlap**
- [ ] OLED update 1s **tidak skip** walau PZEM 7s blocking
- [ ] Energy data ke Firebase **max 2s delay** dari sensor read
- [ ] Binary < 1.2MB flash, RAM < 200KB
